# 手机 App 功能清单

写给下一步做计划用。**现状**：M1 控制面已完成并真机验收（见 `2026-09-18-phone-app-design.md` §10）。
本文按"该有什么"排，不按"好做难做"排；每条都标了依赖和优先级，方便砍。

优先级标记：**P2 必做** = 这期就要 / **P2 顺带** = 同一套东西多做一点 / **将来** = 先记着。

## 1. 设备配置面 —— **这一块现在就能做，不需要等 SoftAP**

设备菜单里已有的设置全部搬进 App。走的还是 BLE 上那套帧（`0x10 CFG_GET` / `0x11 CFG_SET` /
`0x12 CFG_RESET` + Pico 侧的 `0x04 CONFIG` / `0x06 LED` / `0x03 STATUS`），**不依赖 P2 的 HTTP**，
所以可以立刻开工，是投入产出比最高的一块。

### 1.1 手柄

- 按键映射：点一个键 → 选要绑的功能（现在得在 240×135 的屏幕上一个个翻）
- 去抖延迟、输入历史开关、按键布局
- **配置档 1–5**：设备菜单里那三项是死 UI（定义了但没实现），做 App 时顺手在固件补上
- 改完即时生效；「保存到设备」才写 flash（跟设备菜单的语义一致，避免频繁写 flash）

### 1.2 灯光

- 灯效选择、颜色（色环取色）、亮度、动画速度
- 预览：改动即时下发，看着手柄改

### 1.3 显示 / 背景

- 主题、壁纸切换、透明度、背光亮度、水平/垂直翻转、反色
- 屏保模式与息屏时间（注意：动态壁纸开启时屏保会被固件强制关掉，App 要如实显示）

### 1.4 无线 / 蓝牙

- nRF 无线开关、重新配对（对应设备菜单「无线」页）
- 蓝牙开关、**改设备名**、**改配对码 / 清除配对**（清配对会让所有手机掉线，要二次确认）
- 当前连接数、广播状态
- 明确提示互斥关系：蓝牙开 ⇒ nRF 停（固件里就是这么干的，App 不能装作没事）

**依赖**：固件侧新增 `0x05` 一类"下发单条设置"的帧（现有的 `0x11 CFG_SET` 是 17 字节整包镜像，
适合"读一次改一项写回去"，够用；只是要确认读写时序别和设备菜单打架）。

## 2. 数据面：壁纸（P2 必做，走 SoftAP + HTTP）

大文件走 BLE 不现实（MTU 23 时一帧 20 字节），所以这一块**必须先有设备端 SoftAP + HTTP**。

### 2.1 壁纸 / 开机动画

- 从手机相册选 GIF / 图片 → **手机端转 `.gfr`**（必须与 PC 助手输出逐字节一致，否则等于两套格式）
- 上传到设备 `/wp/` → 传完自动生效，不用重启
- 进度、取消、失败重试、断网续传
- 多张壁纸：列表（缩略图 + 占用空间）、切换、删除
- 上传时给出手机端预计耗时（2.5 MB / 30 秒是验收线）

### 2.2 游戏 ROM —— **不做**（2026-09-20 定）

用户明确不做 ROM 上传。理由：传 ROM 的时候人必然在电脑边上（ROM 本来就在电脑里），
配置助手顺手就做了，App 里再实现一套没有增量价值。

只保留**只读**的一小块，折进存储总览：「设备上装了哪几个 ROM、各占多少、卡还剩多少」。
这跟壁纸页读的是同一份 `/api/list`，几乎零成本；如果你连这个都不想要，删掉即可。

**依赖**：设备端 SoftAP + HTTP（固件侧还没做，是 P2 的第一件事）。

## 3. 设备管理

- **多设备记忆**：列表里存多台手柄（名字 + 地址），一键切换
- **自动重连**：打开 App 尝试直连上次设备，不用每次扫
- 忘记设备 / 解绑（清掉本地存的配对码）
- 设备改名入口（见 1.4）
- 设备状态卡片：固件版本、协议版本、卡空间、内存、已连手机数（M1 已有，挪到首页更顺眼）

---

## 4. 诊断（这个项目特别需要，建议早做）

现在排查靠插数据线读串口，App 做出来就不用插线了：

- **实时日志流**：把固件 `dbgSink` 的输出经 BLE 推到 App（设备侧只是多个 `0x06 LOG` 命令）
- **帧监视器**：HEX + 解析后的收发记录，等于把串口终端装进手机
- **一键体检**：PING 往返延迟、协商到的 MTU、一个 INFO 回包分了几片、读写速率
- **导出日志**：打包成文件直接分享（发给作者时不用再教人插线抓串口）
- 内部堆 / PSRAM / 帧率曲线（固件已经有 `[heap]` 那块数据）

---

## 5. 固件升级（OTA）—— **不做**（2026-09-20 定）

理由（用户拍板）：

- 更新路径已经由**配置助手 + USB** 覆盖：谁需要更新，就给他装配置助手。
- 远程帮人修也一样——给配置助手，不是给 OTA。
- Win7 那台太老，本来也不打算彻底支持，不该拿它当论据。

**保底知识**（万一以后要做）：

- 现在分区表 `app0 @0x10000 4MB` / `spiffs @0x410000`，`otadata @0xe000` 已经预留。
  切成 `app0 2MB + app1 2MB` 正好让 spiffs 起点不变，**卡里的壁纸和 ROM 不丢**。
- 但切分区表**必须插线刷一次才生效**，所以真要做得在设备送出去之前切。
- 刷的时候**别刷 `merged.bin`**（16 MB 整包会把 spiffs 区一起写掉，卡里东西全没），
  要单独刷 bootloader + partitions + app；`arduino-cli upload --input-dir` 走的就是安全那条路。

## 7. 建议顺序

1. **诊断（第 4 节）先做最小版**：日志流 + 帧监视器。后面每一块都要靠它排查，早做早省事。
2. **配置面（第 1 节）**：不依赖任何固件大改，投入产出比最高，做完 App 就"有用"了。
3. **数据面（第 2 节）**：先做固件 SoftAP + HTTP，再做 App 上传。开工前先修固件两处
   （TX 单缓冲在多帧连发时会丢回包；传完重载壁纸要确认 `gifInit()` 重复调用不泄漏 PSRAM）。
4. **设备管理（第 3 节）**：有 2、3 之后自然要做。

## 8. 已拍板（2026-09-22）

1. **`.gfr`**：用和配置助手同一套压缩，只要求格式合法 + 体积不膨胀，**不要求字节一致**
2. **首页**：底栏式
3. **日志**：要落盘（掉线后还能翻历史）
4. **浅色主题 / 英文**：不做
5. **NES 只读列表**：不做

## 9. 历史：当初需要拍板的

1. **多设备**要支持几台？只服务你自己这一台的话，第 3 节可以砍掉一半
2. **要不要英文界面**（不做的话第 6 节的"中英文"删掉）
3. **诊断页要不要对用户可见**（我倾向：藏起来，连点版本号 5 次才出现）
4. **NES 只读列表要不要**（2.2 留的那一小块）
5. **`.gfr` 的"与配置助手一致"怎么定义**（详见实现方案 §5.3，我建议只要求格式合法 + 观感一致）

## 10. 明确不做

- **蓝牙当游戏输入**：延迟差一个数量级（nRF 一包 0.3–0.5 ms vs BLE 端到端 15–30 ms），
  设备端已经做成互斥（蓝牙开 ⇒ nRF 停）。App 只做配置通道。
- **账号 / 云同步**：本地就够，加了要维护服务端，还得管隐私合规。
- **OTA 固件升级**：用配置助手 + USB（见第 5 节）。
- **NES ROM 上传**：用配置助手（见 2.2）。
